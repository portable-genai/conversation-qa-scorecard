# Common-base practices audit

- **Repo:** `conversation-qa-scorecard`
- **Catalog id:** E3 (package `conversation_qa_scorecard`, env prefix `CONVQA`)
- **Catalogue reference:** [`common-base-practices.md`](https://github.com/portable-genai/.github/blob/main/common-base-practices.md) (checks A1..G7)

This file ships PRE-FILLED with the verdicts the template can honestly claim on the day the repo
is rendered, so a new repo never enters the audit matrix owing an unwritten audit. It is not a
claim that the repo was inspected: re-run each check against the tree and correct the row before
citing this as evidence. The rows marked GAP are the day-one work list, in priority order.

Applicability: a rendered repo ships an `agent/` surface (tool functions plus the A2A card
served at `/.well-known/agent-card.json`), a `ui/` micro-frontend and a full `scripts/` demo
surface, so `[ui]` and `[demo]` checks apply on day one. `infra/terraform/` is the full
stack, so the `[infra]` checks apply too. The agent is scaffolded
and tested but not yet registered with Hrz3; see the R4 row in `COMPLIANCE.md`. A repo with no
user-facing surface should run `make drop-ui` and mark the `[ui]` rows N/A, rather than leaving
a UI half-wired.
**Load-bearing** checks (a FAIL breaks a shared catalog guarantee) are A1-A6, C1-C5, D1-D3 and E1.

Two findings are recorded here rather than fixed directly in this repo alone, because fixing
either here alone would diverge it from the fleet.

- **The UI's `script-src 'self'` policy and Next.js 16's hydration bootstrap.** A nonce alone is
  not sufficient: Next can only stamp a nonce onto a DYNAMICALLY rendered route, so a statically
  prerendered route carries no nonce, and `'strict-dynamic'` additionally disables the `'self'`
  fallback needed to load chunk scripts. The working form is the nonce plus
  `export const dynamic = "force-dynamic"` in
  `app/layout.tsx`, with `assertHydratableCsp` refusing any build where the two disagree and
  `ui/scripts/assert-hydratable.mjs` proving, against a served production build, that every
  script tag carries the served nonce. Verified in a browser: 9 of 9 script tags nonced and
  hydrated.
- **The UI proxy makes the API see a forwarded header.** Under the deliberate offline `local`
  profile the exposure guard then refuses, correctly, because the peer address can no longer be
  established. Running the two together locally needs `CONVQA_ALLOW_INSECURE_DEMO=1`, which is
  documented in `docs/runbook.md` and is the intended opt-in rather than a defect.
